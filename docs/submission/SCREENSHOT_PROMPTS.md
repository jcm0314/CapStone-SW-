# 사업계획서 「5. 제품 이미지」 캡처 가이드

사업계획서에 넣을 화면 7장을 누가 찍어도 같은 결과가 나오도록 정리한 문서입니다.
사람이 직접 따라 해도 되고, 다른 Claude 세션에 맨 아래 **「세션용 프롬프트」**를 그대로 붙여 넣어도 됩니다.

## 공통 조건

| 항목 | 값 |
|---|---|
| 주소 | https://hr-evaluator-frontend-pt3ki5ggua-du.a.run.app/ (**최신 main 재배포 후** 찍을 것) |
| 브라우저 창 | 1440 × 900, 확대 100%, 라이트 모드 |
| 회사 | 상단 회사 선택이 "토스페이먼츠"인 상태 그대로 |
| 파일 형식 | PNG, `docs/submission/screens/` 에 아래 파일 이름으로 저장 |
| 금지 | 실제 사람의 자소서·개인정보 사용 금지. 아래 데모 자소서 A, B만 사용 |
| 비용 | AI 평가 1건에 약 7원. A, B 두 건이면 충분 |

재배포 여부 확인: 첫 화면 문구가 "AI 분석은 30초 안팎"이고 로고가 파란 "C · CHECK-MATE"이면 최신입니다.
"1.5분이면 끝납니다"가 보이면 옛 버전이니 찍지 마세요.

## 준비: 평가 2건 만들기

1. 첫 화면에서 **무료로 시작하기** → 왼쪽 메뉴 **새 평가**
2. 데모 자소서 A (정하늘, 백엔드)
   - 직무: **소프트웨어 엔지니어**
   - **직접 입력** 탭에 아래 「데모 자소서 A」 전문을 붙여 넣기
   - 이름 칸에 "정하늘"이 자동으로 들어갔는지 확인하고, 비어 있으면 직접 입력
   - **평가 실행** → 개인정보 동의 창이 뜨면 동의 → 30초 안팎 대기
3. 데모 자소서 B (최유나, 영업)도 같은 방법으로 평가하기. 직무는 **B2B 영업 & 사업개발**로 고르기

AI 결과는 실행할 때마다 조금씩 다릅니다. 아래 화면별 "통과 조건"을 만족하지 않으면 그 자소서를 한 번 더 평가하세요 (최대 3번).

## 화면별 지시

### 01_landing.png — 첫 화면
- **목적**: 무엇을 하는 서비스인지 한눈에 보여 주기
- **조작**: 첫 화면 맨 위에서 캡처
- **범위**: 화면 전체 (1440 × 900)
- **통과 조건**: 큰 제목, "AI 분석은 30초 안팎" 문구, 파란 버튼 두 개가 모두 보임

### 02_highlight.png — 형광펜 결과
- **목적**: 자소서 문장마다 근거 색이 칠해지는 핵심 기능
- **조작**: 지원자 A 결과 화면 → 아래 **근거 문장** 섹션 → **자소서 전문 보기** 펼치기
- **범위**: 근거 카드 일부 + 펼친 자소서 원문
- **통과 조건**: 초록(숫자 성과), 주황 점선(면접 확인), 분홍 물결(과장) 세 가지 색이 모두 보임

### 03_interview_question.png — 숫자 모순을 잡은 면접 질문
- **목적**: "진짜·가짜 검증" 메시지의 대표 장면
- **조작**: 지원자 B 결과 화면 → **면접 질문** 섹션에서 연간 목표(60건)와 분기 합계(56건)를 묻는 질문 찾기 → 그 질문의 **질문 의도 · 면접관 체크리스트** 펼치기
- **범위**: 그 질문 카드 하나 (질문, 근거 문장, 펼친 체크리스트)
- **통과 조건**: 질문 안에 "60"과 "56"이 둘 다 나옴. 없으면 B를 다시 평가

### 04_pii_masked.png — 개인정보 가리기
- **목적**: AI가 이름·학교·연락처를 보지 않는다는 증거
- **조작**: 지원자 A 결과 화면 → **자소서 전문 보기** 펼친 상태에서 첫 문단으로 스크롤
- **범위**: 첫 문단 주변
- **통과 조건**: `[성명 익명화]`, `[학교명 익명화]`, `[전화번호 익명화]`, `[이메일 익명화]`, `[거주지역 익명화]`가 보이고, "정하늘", "한빛대학교", "010-"은 보이지 않음

### 05_hitl.png — 사람 검토(HITL)
- **목적**: AI는 초안이고 최종 판단은 사람이 한다는 장면
- **조작**: 지원자 A 결과 화면 → 위쪽 **사람 검토(HITL) 보정** 버튼 → 열린 창에서 역량 점수 하나를 조금 바꿔 둔 상태
- **범위**: 열린 창 전체
- **통과 조건**: 점수 수정란과 근거 수정 영역이 함께 보임. 저장은 누르지 않아도 됨

### 06_share.png — 면접관 공유
- **목적**: 링크 하나로 면접관끼리 메모와 점수를 나누는 장면
- **조작**:
  1. 지원자 A 결과 화면 → **면접관 공유** → **링크 복사**
  2. 새 창(시크릿 창 권장)에서 그 링크 열기
  3. 아래 **면접관 메모**에 "Q2 팀원 역할을 구체적으로 답함. 서버는 본인 담당 확인" 입력 후 **등록**
- **범위**: 공유 화면 상단 안내 + 면접관 메모 영역
- **통과 조건**: 공유 링크로 열린 화면이라는 표시와 방금 쓴 메모가 함께 보임

### 07_feedback.png — 지원자 피드백
- **목적**: 탈락자에게도 강점과 보완점을 알려 준다는 장면 (청년 구직자 관점)
- **조작**: 지원자 A 결과 화면 → **지원자 피드백** 버튼
- **범위**: 열린 창 전체
- **통과 조건**: "강점"과 "보완" 항목에 자소서 문장이 인용되어 보임

[직무 관련 경험]
커머스 스타트업에서 6개월간 백엔드 인턴으로 일했습니다. 주문 조회 API의 평균 응답 시간이 2.8초여서 장바구니 이탈 문의가 매주 들어왔습니다. 쿼리 로그를 확인해 보니 상품 옵션을 불러올 때 같은 쿼리가 반복되고 있었습니다. 저는 조인 쿼리를 하나로 묶고, 자주 조회되는 상품 정보에 Redis 캐시(TTL 5분)를 적용했습니다. 그 결과 평균 응답 시간을 0.4초로 줄였습니다.

[프로젝트 경험]
5명이 함께한 졸업 프로젝트 '동네 중고거래 앱'에서 저는 서버 전체를 혼자 설계하고 개발했습니다. 채팅, 결제, 알림 기능을 모두 제가 만들었고, 덕분에 팀은 교내 경진대회에서 대상을 받았습니다. 출시 후 첫 달에 가입자 1,200명을 모았고, 둘째 달에는 가입자가 두 배로 늘어 총 2,000명이 되었습니다.

## 세션용 프롬프트

다른 Claude 세션(브라우저를 다룰 수 있는 세션)에 아래를 그대로 붙여 넣으세요.

```text
레포의 docs/submission/SCREENSHOT_PROMPTS.md 를 처음부터 끝까지 읽고, 그 문서의 지시대로 사업계획서용 화면 7장을 캡처해 줘.

지켜야 할 것:
- 「공통 조건」의 주소·창 크기·라이트 모드를 지키고, 첫 화면에서 재배포 여부부터 확인해. 옛 버전이면 캡처하지 말고 나에게 알려 줘.
- 자소서는 문서에 있는 데모 자소서 A, B만 써. 다른 텍스트를 지어내지 마.
- 화면마다 「통과 조건」을 직접 확인하고, 만족하지 않으면 그 자소서를 다시 평가해(최대 3번). 그래도 안 되면 그 화면은 건너뛰고 이유를 적어.
- 결과는 docs/submission/screens/01_landing.png ~ 07_feedback.png 로 저장해.
- 끝나면 화면별로 "저장함 / 건너뜀(이유)" 표와, AI 평가를 몇 번 실행했는지 알려 줘.
```

## 도표 (그림 1·2·6)

사업계획서의 도표 3개는 `docs/submission/diagrams/diagrams.html` 한 파일에 있습니다.
글자나 숫자를 고친 뒤 아래처럼 PNG로 다시 뽑으면 됩니다 (Chrome과 playwright-core 필요, 2배 해상도).

```bash
npm i --no-save playwright-core@1.48.2
node -e "
const {chromium}=require('playwright-core');
(async()=>{const b=await chromium.launch({executablePath:'/usr/bin/google-chrome'});
const p=await b.newPage({viewport:{width:1280,height:900},deviceScaleFactor:2});
await p.goto('file://'+process.cwd()+'/docs/submission/diagrams/diagrams.html',{waitUntil:'networkidle'});
for (const [id,f] of [['fig-problem','d1_problem'],['fig-solution','d2_structure'],['fig-roadmap','d3_roadmap']])
  await p.locator('#'+id).screenshot({path:'docs/submission/diagrams/'+f+'.png'});
await b.close();})()"
```

도표의 숫자는 실측값(`scripts/bench/`)과 사업계획서 로드맵에 있는 값만 씁니다.
