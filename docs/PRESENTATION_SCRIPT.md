## [Slide 02] 문제 인식 : 채용 현장의 3대 병목 (심사항목 1 · 25점) (0:30 ~ 1:15)
먼저 프로젝트 배경입니다. 화면의 4컷 만화는 스타트업 실무 팀장인 '김과장'이 겪는 채용 현장의 모습입니다.
현재 채용 현장은 세 가지 병목을 겪고 있습니다.
첫째, 지원서 분량은 폭증했지만 전담 인사 검증 인력이 부족한 스타트업·중소기업에서는 현업 실무자가 밤늦게 수백 장의 이력서를 수기로 읽어야 합니다.
둘째, 팀 프로젝트 성과를 개인 성과로 부풀린 서류를 사전에 걸러내지 못해 면접 리소스가 낭비됩니다.
셋째, 지원자 실명과 연락처가 담긴 원문을 외부 AI에 그대로 입력할 때의 개인정보 유출 위험과, 엑셀·노션에 파편화된 면접 평가 취합의 비효율이 존재합니다.

## [Slide 03] 해결방안의 창의성 및 차별성 (심사항목 1 · 25점) (1:15 ~ 2:00)
기존 채용 관리 솔루션(ATS)은 단순 문서 뷰어라 서류 내용의 진위를 검증하지 못하고, 범용 단일 프롬프트 AI는 지원자의 과장된 주장을 비판 없이 요약하거나 원문에 없는 할루시네이션을 생성합니다.
Check-Mate는 이를 해결하기 위해 **① 근거를 발췌하는 에이전트와 이를 적대적으로 반박하는 Critic 에이전트를 분리**했고, **② 로컬과 서버 이중 방어선에서 7종 개인정보를 비식별화**하며, **③ 3단계 퍼지 매칭으로 원문 위에 3색 형광펜을 바인딩**하는 5단계 파이프라인을 구축했습니다.

---

## [Slide 04] 핵심 설계 ① : 4대 멀티에이전트 적대적 교차 검증(DAG) (심사항목 4 · 25점) (2:00 ~ 3:00)
핵심 기술 첫 번째는 **4대 멀티에이전트 적대적 교차 검증 파이프라인**입니다.
Stage 1에서 **Grounding 에이전트**가 자소서 본문 내 정량 성과와 경험 문장을 원문 그대로 발췌하면, Stage 2에서 **Critic 에이전트**가 이를 넘겨받아 기여도 과장과 수치 비약을 적대적으로 반박합니다.
이어서 Stage 3과 Stage 4에서는 `Promise.all` 병렬 실행을 통해 **Supervisor 에이전트**가 5대 역량 점수를 채점하고, 동시에 **Interviewer 에이전트**가 Critic이 적발한 취약 구간을 검증할 압박 면접 질문 3종을 생성합니다. 모든 출력은 JSON 스키마를 강제하며, 오류 시 가짜 점수로 폴백하는 것을 전면 금지했습니다.

## [Slide 05] 핵심 설계 ② : 이중 방어선 7종 PII 비식별화 (심사항목 4 · 25점) (3:00 ~ 3:45)
두 번째 핵심 설계는 **이중 방어선 7종 개인정보 비식별화**입니다.
브라우저 로컬에서 1차 마스킹을 수행한 뒤, API 우회 호출까지 방어하기 위해 Cloud Run BFF 게이트웨이에서 동일한 7종 정규식 파이프라인을 2차 강제 수행합니다.
특히 학교명 치환 시 '대학원', '대학생', '대학교육'이 오탐되지 않도록 **부정형 전방탐색(`(?!원|생|교)`)**을 적용했고, 전역 정규식 재사용 시 `lastIndex = 0` 초기화로 상태 오염을 방지했습니다.

## [Slide 06] 핵심 설계 ③ : 3단계 퍼지(Fuzzy) 원문 매칭 알고리즘 (심사항목 4 · 25점) (3:45 ~ 4:45)
세 번째 핵심 기술은 AI가 발췌한 인용구를 원문 오프셋 좌표로 복원하는 **3단계 퍼지 매칭 엔진**입니다.
PDF 줄바꿈이나 LLM의 미세한 조사 변형으로 인해 단순 `indexOf`가 실패하는 문제를 해결하기 위해 3단계 폴백 구조를 설계했습니다.
- **Stage 1**은 `indexOf` 기반 완전 일치 탐색으로, 일치 시 $O(N)$에 즉시 좌표를 반환합니다.
- **Stage 2**는 **Word Anchor & Jaccard N-gram 필터링**입니다. 공백·개행 정규화 후 인용구의 첫 어절(`firstWord`)과 끝 어절(`lastWord`)을 경계 앵커로 고정하여 후보 구간을 추출하고, 어절 N-gram 교집합 비율(Jaccard 유사도)로 무관한 문장 구간을 빠르게 배제합니다.
- **Stage 3**은 **Dynamic Sliding Window + Levenshtein DP**입니다. 인용구 길이 $L$ 대비 $\pm 20\%$($0.8L \sim 1.2L$) 범위의 가변 윈도우를 슬라이딩하며 2차원 동적 계획법(Levenshtein Edit Distance DP)을 수행해, 정규화 유사도가 $0.85$ 이상인 최적의 원문 시작·끝 좌표를 복원합니다. 모든 연산은 **Web Worker** 백그라운드 스레드에서 실행되어 UI 블로킹이 전혀 발생하지 않습니다.

## [Slide 07] 전체 시스템 아키텍처 및 기술 스택 (심사항목 4 · 25점) (4:45 ~ 5:25)
전체 시스템 아키텍처입니다.
클라이언트는 **React 18, Vite, Tailwind, Web Worker**로 구성되며, 서버는 **GCP Cloud Run** 위에 **Express BFF와 Spring Boot 3**를 연동했습니다.
추론 엔진은 서버 전용 API 키로 격리된 **Anthropic Claude Haiku 5.5**를 호출하며, 데이터베이스는 **Supabase PostgreSQL**을 사용합니다.

---

## [Slide 08] 멀티테넌트 DB 스키마(ERD) 및 RLS 격리 (심사항목 4 · 25점) (5:25 ~ 6:05)
데이터베이스 설계입니다. 좌측은 실제 구축된 Supabase 7개 핵심 테이블 스키마(ERD)입니다.
단일 DB 내에서도 토스페이먼츠, 당근, 우아한형제들 같은 고객사 데이터가 섞이지 않도록 모든 테이블에 `tenant_id = current_tenant_id()` **Row-Level Security(RLS) 격리 정책**을 적용했습니다.
또한 정형 메타데이터는 일반 컬럼으로 인덱싱하고, 에이전트가 도출한 근거·질문 배열은 `JSONB`로 저장하는 하이브리드 구조를 채택했습니다.

## [Slide 09] 구현 결과 ① : STEP 1 ~ STEP 3 화면 (심사항목 4 · 25점) (6:05 ~ 6:45)
실제 프로덕션 구현 화면입니다.
**STEP 1**은 기업별 데이터 격리 및 4단계 RBAC 역할 스위처이고, **STEP 2**는 신규 자소서 `정하늘.pdf` 업로드 시 성명과 본문을 자동 추출하는 화면입니다.
**STEP 3**은 7종 개인정보가 익명화된 본문 위에 3단계 퍼지 매칭을 통해 녹색 긍정 근거와 적색 과장 리스크가 1:1 형광펜으로 표시되는 화면입니다.

## [Slide 10] 구현 결과 ② : STEP 4 ~ STEP 6 화면 (심사항목 4 · 25점) (6:45 ~ 7:25)
**STEP 4**에서는 과장·모순 의심 구간을 검증할 맞춤형 압박 질문 3종과 면접관 빠른 채점 메모를 제공하며, **STEP 5**에서는 채용 담당자가 AI 초안 점수를 직접 보정하고 감사 로그에 기록합니다.
**STEP 6**에서는 가중치 슬라이더 조절 시 AI 재호출 없이 즉시 지원자 순위를 재계산하고 N-gram 표절 매트릭스를 제공합니다.

## [Slide 12] 목표 시장 및 3대 타겟 고객 (심사항목 2 · 20점) (8:00 ~ 8:40)
시장성 측면에서 Check-Mate는 3단계 시장을 공략합니다.
**1차 핵심 시장**은 전담 HR 검증 인력이 부족한 **IT 스타트업·중소기업 채용팀**이며, **2차 확장 시장**은 블라인드 채용과 감사 로그가 의무화된 **공공기관·중견기업**, **3차 확산 시장**은 구직자 셀프 진단 모드를 활용한 **대학 취업지원센터**입니다.

---

## [Slide 13] 3-Tier 수익모델 및 단위 경제성 (심사항목 2 · 20점) (8:40 ~ 9:20)
수익모델은 DB `tenants` 테이블에 실제 구현된 **3-Tier SaaS 월 구독 + AI 평가 크레딧 하이브리드 모델**입니다.
특히 **Claude Haiku 5.5 경량 파이프라인**으로 자소서 1건당 API 호출 원가를 수십 원 이하로 낮췄고, 형광펜 매칭과 가중치 재계산을 Web Worker와 DB 연산으로 처리해 **AI 재호출 제로(Zero Re-call)** 고마진 구조를 완성했습니다.

## [Slide 14] 실현 가능성 · 사업화 로드맵 · 팀 역량 및 Q&A (심사항목 3·5 · 25점) (9:20 ~ 10:00)
Check-Mate는 이미 GCP Cloud Run 실배포와 자동화 테스트를 마친 Phase 1 상태에서, 대학 및 스타트업 PoC를 거치는 Phase 2, 기업 맞춤형 Prompt Studio와 ATS 연동을 추진하는 Phase 3으로 사업화를 확장해 나가겠습니다.
기획부터 AI 파이프라인, 프론트·백엔드, 멀티테넌트 DB, 클라우드 배포까지 단독 풀스택으로 완주한 Check-Mate 발표를 마치겠습니다. 감사합니다.
