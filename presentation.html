01

심사 피로도와 주관적 편차

  • • 심사위원 개인 성향과 컨디션에 따른 점수 왜곡
  • • 서류 분량이 많아질수록 정밀 검증 포기
  • • 평가 근거 기록 미비 $\rightarrow$ 탈락자 납득 불가
02

기존 생성형 AI의 환각(거짓말)

  • • 자소서 본문에 없는 경력을 AI가 임의로 지어냄
  • • 단일 프롬프트 채점 시 점수가 실행마다 널뜀
  • • 출처 없는 점수화로 신뢰성 원천 붕괴
03

개인정보(PII) 유출 위험

  • • 성명, 학번, 연락처 노출로 블라인드 위반
  • • 외부 LLM API로 지원서 원문이 그대로 전송
  • • 기업/대학 보안 거버넌스 정책 위반

별첨 02 — 3-Tier 하이브리드 DB 구조 Slide 18 / 23

기존 DB는 그대로 두고, 가상 캐시 레이어만 추가

비침습적(Non-Invasive) 설계로 개발 오버헤드를 줄이고, 비용을 0원으로 만듭니다.

Tier 1 (Client DB)

IndexedDB (HR_AX_DB)

• 자소서 본문 해시 기반 1:1 캐싱
• 한 번 평가된 서류는 재열람 시 API 호출 0회, 비용 0원
• 미지원 브라우저는 LocalStorage로 자동 폴백

Tier 2 (Server Cache)

Redis 7-Alpine

• 분산 환경 동시 접속 세션 관리
• API Rate Limiter로 무차별 호출 차단
• --save 60 1 볼륨 마운트로 재부팅 시에도 유지

Tier 3 (Enterprise DB)

사내 RDBMS (12월 확장)

• 기존 대학/기업 DB 수정 없이 연동
• 2,000명 학번/사번 매핑 크레딧 테이블(`User_Credits`)만 가볍게 추가

별첨 06 — 심사위원 FAQ Slide 22 / 23

자주 나오는 질문과 답 (FAQ 6종)

OmniSite 75페이지의 Q&A 방어 전략을 Check-Mate에 맞게 완벽히 구성했습니다.

Q. LLM이 환각으로 틀린 말을 하면 어떡하죠?

A. 퓨지 매처가 원문에서 해당 문장을 찾지 못하면 즉시 [미매칭 경고]를 띄우며, 점수에 반영되지 않도록 Human-in-the-Loop 모달에서 관리자가 즉시 삭제할 수 있습니다.

Q. 왜 제일 똑똑한 GPT-4o를 안 썼죠?

A. GPT-4o는 건당 41.5원이 들어 2천 명 평가 시 10만 원이 깨집니다. 4대 에이전트 분업 덕분에 Gemini Flash-Lite(1.2원)로도 93.8%의 플래그십급 정확도를 유지함을 실측했습니다.

Q. 개인정보를 마스킹하면 역량 평가가 왜곡되지 않나요?

A. 성명과 출신 학교만 [익명화]되며, 지원자가 수행한 프로젝트 설명, 기술 스택, 성과 수치는 100% 보존되므로 순수 직무 역량 기반의 공정 평가가 가능합니다.

Q. 2,000명이 쓰면 비용 폭탄 맞지 않나요?

A. 새로 구축한 부서별 크레딧 쿼터 대시보드에서 부서별 상한액($100~$500)에 도달하면 Auto-Quota Lock이 발동되어 무단 과소진을 시스템적으로 원천 차단합니다.

Q. 기존 학사/인사 DB를 뜯어고쳐야 하나요?

A. 아닙니다. IndexedDB와 Redis 캐시 레이어로 동작하는 비침습적 설계이므로, 기존 DB에 User_Credits 테이블만 얹으면 즉시 연동됩니다.

Q. 다른 대학교나 기업에도 적용 가능한가요?

A. 네, 프롬프트 스튜디오에서 직무 가중치와 인재상 템플릿만 바꾸면 캡스톤 보고서 채점부터 기업 공채까지 코드 변경 없이 즉시 호환됩니다.
