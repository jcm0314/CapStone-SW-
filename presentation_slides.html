핵심 설계 ② : 이중 방어선 7종 개인정보(PII) 비식별화

외부 LLM 전송 전 브라우저 로컬(1차)과 Cloud Run BFF 서버(2차)에서 개인정보 유출 원천 차단

클라이언트 · 서버 이중 비식별화 파이프라인 (piiAnonymizer.js) Zero-PII Leakage 보장
7종 개인정보 비식별화 규칙 명세 정규식 정밀 설계
비식별 항목 탐지 패턴 및 오탐 방지 기법 치환 결과 토큰
1. 지원자 성명 escapeRegExp(applicantName) 동적 정규식 생성 [성명 익명화]
2. 출신 학교명 부정형 전방탐색 /[가-힣]+대학교?(?!원|생|교)/g [학교명 익명화]
3. 전화번호 휴대전화(010) 및 지역번호 하이픈·공백 변형 매칭 [전화번호 익명화]
4. 이메일 주소 계정 로컬 파트 및 도메인 전체 RFC 패턴 매칭 [이메일 익명화]
5. 주민등록번호 생년월일 6자리 + 성별코드([1-4]) 7자리 패턴 [주민번호 익명화]
6. 상세 거주지 주소 시·도 / 구·군 / 도로명·번지·아파트 동·호수 결합 패턴 [주소 익명화]
7. 학번 · 사번 ID 문맥 키워드 결합 7~10자리 고유 식별 번호 패턴 [고유ID 익명화]
핵심 엔지니어링 포인트 3가지
1. 부정형 전방탐색 오탐 방지
단순 치환 시 '대학교육', '대학원', '대학생'까지 마스킹되어 문맥이 깨지는 문제를 /[가-힣]+대학교?(?!원|생|교)/g로 정밀 해결
2. RegExp 상태 오염 방지
전역 정규식(/g) 연속 호출 시 lastIndex = 0 강제 초기화 및 불변 문자열 파이프라인으로 누락 없는 멱등성 보장
3. 학벌·신상 편향 원천 제거
AI 에이전트와 면접관 모두 지원자의 출신 대학·연락처를 알 수 없는 완전 블라인드 실력 중심 평가 달성

핵심 설계 ③ : 3단계 퍼지(Fuzzy) 원문 오프셋 바인딩 알고리즘

Word Anchor & Jaccard N-gram 후보 필터링과 Dynamic Sliding Window + Levenshtein DP 결합

STAGE 1 · Fast-Path 시간복잡도 O(N)
Exact IndexOf 완전 일치 탐색
rawText.indexOf(targetQuote)
→ 일치 시 즉시 [start, end] 반환 (Sim = 1.0)
• AI 인용구가 원문과 정확히 일치할 경우 무거운 DP 연산 없이 즉시 좌표 확정
• PDF 줄바꿈(\n)·다중 공백 불일치 시 Stage 2로 자동 폴백
1차 필터: 불필요한 편집거리 연산 제거
STAGE 2 · 후보 구간 압축 탐색 공간 대폭 축소
Word Anchor & Jaccard N-gram 필터링
• Word Anchor: firstWord ~ lastWord 경계 고정
• Jaccard N-gram: J(A, B) = |A ∩ B| / |A ∪ B|
• 공백·개행 정규화 후 시작·끝 어절 위치를 앵커링하여 후보 슬라이스 추출
• 어절 N-gram 교집합 유사도가 낮은 무관한 문장 구간 사전 배제
2차 필터: 전체 본문 브루트포스 스캔 방지
STAGE 3 · 정밀 오프셋 복원 임계값 Sim ≥ 0.85
Dynamic Sliding Window + Levenshtein DP
• 가변 윈도우: 길이 L 기준 [0.8L, 1.2L] (±20%)
• 정규화 유사도: Sim = 1 - D_lev(W, Q) / max(|W|, |Q|)
• LLM이 조사나 어미를 일부 축약·변형한 경우에도 가변 윈도우(stride = 3, Δw = 5)와 2D DP로 최적 원문 구간 복원
3차 복원: Sim ≥ 0.85 최적 오프셋 확정
Word Anchor 경계 탐색 및 Dynamic Sliding Window + Levenshtein DP 작동 구조도 Web Worker 백그라운드 스레드 실행 (UI 블로킹 제로)
